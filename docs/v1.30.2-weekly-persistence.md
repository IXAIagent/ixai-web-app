# IXAI v1.30.2 Weekly Persistence + Scheduled Draft Generation

## Scope

v1.30.2 turns Weekly Intelligence from an Editorial Studio scaffold into an operating workflow:

1. Weekly draft generation
2. Editorial Studio review
3. Manual preview
4. Manual publish
5. Public reading from published Weekly Intelligence only
6. Draft / review / published / archived history

This does not change the real-time Market Intelligence Layer, watchlist, quotes, FCN engine, auth/session architecture, or CRM schema.

- Service role must never be exposed to client code.

## Weekly Generation Rule

Weekly drafts use a Monday-to-Sunday operating week.

Vercel Cron runs at:

- `0 0 * * 0` UTC
- Sunday 08:00 Asia/Taipei

At that time, IXAI generates a draft for the week ending on that Sunday:

- `week_start = Monday`
- `week_end = Sunday`

Slug format:

- `weekly-intelligence-YYYY-MM-DD`

Duplicate prevention:

- If the same `week_start` / `week_end` already exists, the generate API returns the existing draft.
- `force=1` may generate a new slug with a timestamp suffix.

- `POST /api/admin/weekly-briefs/generate`
- `GET /api/admin/weekly-briefs/[id]`

- `GET /api/weekly-briefs/latest`
- `GET /api/weekly-briefs/[slug]`

Cron:

- `POST /api/cron/generate-weekly-brief`

## Cron Security

Required Vercel Environment Variable:

- `CRON_SECRET`

The route also accepts the existing `IXAI_CRON_SECRET` fallback for continuity.

Accepted token locations:

- `x-cron-secret` header
- `Authorization: Bearer <secret>`
- `?token=<secret>`

Cron only creates a draft. It never publishes.

## Editorial Guardrails

Weekly publish requires:

- manual admin session
- existing title
- existing summary
- market highlight sections
- IXAI Intelligence Summary

AI-assisted content must be reviewed before publish.

Weekly content must not include:

- buy/sell instructions
- target prices
- guaranteed returns
- personal FCN risk monitoring

FCN content remains education-oriented market observation only.

## Fallback Behavior

If Supabase env or table is unavailable:

- Admin can continue using safe in-memory fallback during local development.
- Public Weekly can still render static editorial fallback content.
- No raw Supabase errors are shown in public UI.

Production should apply the migration and configure service role write access before relying on scheduled weekly publishing.
