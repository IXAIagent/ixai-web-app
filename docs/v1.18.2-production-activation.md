## Migration Status

Migration file:

```txt
supabase/migrations/002_daily_intelligence_persistence.sql
```

Status: ready to apply in Supabase production. The migration is non-destructive:

- Uses `create table if not exists`.
- Uses `create index if not exists`.
- Does not drop, truncate, or rewrite existing data.

Table:

```txt
public.ixai_daily_intelligence_drafts
```

Schema coverage:

- `source_id`: stable app-side draft id used for upsert.
- `slug`: public route id.
- `status`: `draft | review | published`.
- `title`, `market_summary`, `editorial_note`.
- `sections`, `risk_focus`, `watchlist_notes`, `intelligence` as JSONB.
- `source_mode`, `provider_mode`, `input_news_count`, `source_status`.
- `generated_at`, `published_at`, `created_at`, `updated_at`.

Indexes:

- `status`
- `published_at desc nulls last`
- unique published slug
- unique active draft/review slug

RLS baseline:

- RLS is enabled.
- Public anon reads are allowed only for `status = 'published'`.
- Admin writes currently use server-only `SUPABASE_SERVICE_ROLE_KEY`, which bypasses RLS.
- Future role-based admin writes should replace service-role writes with Supabase Auth role claims.

Naming note:

- Database columns use snake_case.
- App types expose `publishedAt`, `createdAt`, `updatedAt`.
- Mapping is handled in `src/lib/editorial/persistence.ts`.

## Fallback Verification

Fallback cases:

- Supabase env missing.
- `SUPABASE_SERVICE_ROLE_KEY` missing.
- Table not yet applied.
- Permission denied.
- Supabase timeout.

Behavior:

- Public pages do not white-screen.
- Public UI does not expose raw technical error wording.
- Server logs a concise persistence fallback warning.
- Static editorial Daily Brief remains available.
- Admin review flow remains usable in local fallback mode.

Timeout:

- Supabase REST calls use a short server-side timeout before falling back.

## Admin Safety Verification

Current status:

- `/admin` and `/admin/daily-briefs` use AdminGate.
- Password verification happens server-side.
- Successful admin login sets `ixai_admin_session` as httpOnly, SameSite cookie.
- Browser `sessionStorage` only stores a non-secret UX marker.
- No `x-ixai-admin-hash` bearer-hash path remains.
- `/api/admin/daily-briefs`
- `/api/admin/daily-briefs/draft`
- `/api/admin/daily-briefs/scheduler/status`

All above require admin session.

Scheduler exception:

- `/api/admin/daily-briefs/generate` is a cron endpoint.
- It requires `IXAI_CRON_SECRET` / `CRON_SECRET` through header, bearer token, or query token.
- It does not use browser admin session because Vercel cron cannot depend on a browser cookie.
