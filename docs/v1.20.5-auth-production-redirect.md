# v1.20.5 Auth Production Redirect

## Goal

Production IXAI Account email confirmation must return users to the public app domain:

`https://app.ixuan.ai/auth/callback`

It must not use localhost redirect URLs in production confirmation emails.

## Runtime Redirect Rules

- `NEXT_PUBLIC_SITE_URL` is the preferred public site origin.
- If `NEXT_PUBLIC_SITE_URL` is missing, the app falls back to `https://app.ixuan.ai`.
- Supabase sign-up, magic link, and OAuth handoff use:

`{siteUrl}/auth/callback`

The callback page handles Supabase hash-token confirmations client-side and then redirects to `/account` when a session is available. If a session cannot be established, users are sent back to `/login` with a clear retry message.

## Supabase Dashboard Setup

In Supabase Dashboard:

Authentication -> URL Configuration

Set Site URL:

`https://app.ixuan.ai`

Add Redirect URLs:

- `https://app.ixuan.ai/auth/callback`
- `https://app.ixuan.ai/login`
- `https://app.ixuan.ai/register`
- `https://app.ixuan.ai/account`

Production should not use `http://localhost:3000` as the confirmation redirect.

## Service Worker Safety

The PWA service worker excludes auth-sensitive paths from caching:

- `/auth`
- `/auth/callback`
- `/login`
- `/register`
- `/account`
- `/api/auth`
- session and Supabase-related paths

This prevents stale auth screens or callback URLs from being served from cache.

## Notes

- No service role key is used by client auth.
- No admin auth behavior changed in this version.
- Human/admin content workflows are not affected by the IXAI Account redirect fix.
